# План: регистрация магазина, открытая витрина и безопасная миграция

## Цель
Упростить вход и рост магазинов/клиентов без поломки текущей системы:
- регистрация владельца магазина (оператора) через веб-логин + SMS;
- подключение Telegram после регистрации;
- открытая витрина без обязательной регистрации;
- регистрация клиента только при добавлении в корзину/оформлении;
- персональные ссылки магазинов (slug -> позже поддомены);
- безопасная миграция без даунтайма.

## Что есть сейчас
- Регистрация магазина уже работает через Telegram WebApp.
- Роли: `superadmin`, `moderator`, `operator`, `customer`.
- Есть риск нежелательной смены роли при отдельных регистрационных сценариях.

## Целевое поведение
1. **Оператор/владелец магазина**
- Регистрируется на странице логина (телефон + OTP SMS).
- Получает `operator` аккаунт и создаёт магазин.
- В настройках нажимает “Подключить Telegram” и проходит верификацию.

2. **Клиент**
- Может свободно открыть витрину и смотреть товары без авторизации.
- Регистрация/логин требуется только при:
  - добавлении в корзину;
  - оформлении заказа.

3. **Ссылка магазина**
- Этап 1: `https://talablar.../s/{shop_slug}`.
- Этап 2: `{shop}.talablar.app` (после стабилизации).

## Этапы внедрения

### Этап 0: Защита ролей (обязательно перед всем)
- Запретить автоматическое понижение `superadmin`/`moderator` до `operator`.
- Добавить аудит-лог роли и источника изменения.

### Этап 1: Self-service регистрация магазина через login
- Добавить экран “Регистрация магазина”.
- Поля: ФИО, телефон, OTP, название магазина, тип деятельности, гео.
- Создание `operator` + `restaurant`.
- Telegram-поля сделать опциональными (настройка позже).

### Этап 2: Подключение Telegram после регистрации
- Отдельный мастер в админке магазина:
  - bot token,
  - group id,
  - проверка прав бота,
  - тестовое сообщение.
- Сохранение только при успешной проверке.

### Этап 3: Открытая витрина
- Разрешить просмотр каталога без customer-login.
- Гейт авторизации на `Добавить в корзину` и `Checkout`.
- Добавить SMS OTP вход/регистрацию клиента на этих шагах.

### Этап 4: Персональные ссылки
- Ввести `shop_slug` (уникальный, индекс).
- Роут `s/:slug` -> загрузка нужного магазина.
- Поддомены вынести в отдельный этап после стабилизации slug-модели.

### Этап 5: Миграция и запуск
- Feature flags по этапам.
- Бэкенд сначала backward-compatible.
- Пошаговый rollout: dev -> staging -> production.
- Метрики: конверсия в заказ, OTP success rate, ошибки 4xx/5xx, drop-off до корзины.

## Миграционные правила (чтобы ничего не сломать)
- Не удалять текущий Telegram WebApp flow до полного перехода.
- Новые поля/таблицы добавлять без удаления старых.
- Все критичные изменения под флагами.
- Всегда иметь rollback-переключатель (на уровне env/feature flags).

## Риски и как закрываем
- **Риск:** потеря прав у high-role аккаунтов.  
  **Решение:** hard-guard для `superadmin/moderator`, аудит.

- **Риск:** рост фрода через открытую витрину.  
  **Решение:** rate limit + OTP + anti-spam на checkout.

- **Риск:** путаница с доменами/поддоменами.  
  **Решение:** сначала slug, потом controlled migration на subdomain.
